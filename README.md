# Dropdrop

在一台主机上启动 Dropdrop，同一局域网的设备即可用浏览器上传文件，或输入六位码下载对应批次。发送者上传完成后可以关闭网页，部署主机需要保持运行。

当前版本 `0.1.0-dev.0` 需要从源码安装，CLI 命令为 `dropbin`。

## 从源码启动

使用 [.nvmrc](.nvmrc) 固定的 Node.js 26.13.1。已验证的本地环境为 macOS arm64。如果安装了 nvm，可在仓库目录执行以下命令。

```sh
nvm install
nvm use
npm ci
npm run build
npm start
```

CLI 打印实际访问地址与二维码。默认优先选择可用的物理网卡 IPv4 地址和空闲端口。多网卡时，访问地址下方列出其他候选及对应的 `--host` 参数；自动选择会跳过链路本地或代理虚拟地址。仅在本机试用时，可运行以下命令并打开打印的网址。

```sh
npm start -- --host 127.0.0.1 --port 8787
```

`--max-active-downloads` 设置全局同时下载流数（1–64，默认 4），`--max-active-uploads` 设置全局同时上传流数（1–16，默认 2）。同一接收会话最多同时下载两个不同文件，每个浏览器最多同时上传一个文件。

若需要固定网卡、证书、容量或应用数据目录，运行 `node dist/apps/cli/src/main.js --help`。目录优先使用 `--data-dir`，其次读取 `DROPBIN_DATA_DIR`，否则使用当前用户的系统应用数据目录。首次启动请指定新目录或空的用户专用目录。

## 上传与取件

1. 选择“上传”，添加 1 至 20 个文件，设置最大下载次数、有效期及可选密码。发布后，上传页显示取件码，可查看次数或撤销整批文件。
2. 接收者选择“下载”，输入取件码和访问密码。每个浏览器接收会话在首次有效数据请求时占用一个名额，同一会话下载其他文件或续传共用这个名额。
3. 名额耗尽后，新会话会看到“无下载名额”。已获准的传输可以继续。服务端向已获准的接收会话发完整批文件，或续传窗口结束后，就会清理该批次。批次过期或撤销会中断活动传输。
4. 下载默认交给浏览器的下载管理器。支持保存选择器的安全上下文另有“选择保存位置”入口。手机上的保存位置由浏览器和系统决定。

六位码应当作为短期凭据保管。普通 HTTP 适用于可信局域网；需要加密链路时，以 `--cert` 和 `--key` 配置设备信任的证书。首版重启会使旧批次和会话失效。

## 本机清理

先用以下只读预览核对目标目录与对象数量，目录可替换为实际实例目录。

```sh
node dist/apps/cli/src/main.js cleanup --data-dir ./dropbin-data --dry-run
```

移除 `--dry-run` 会取消传输并清空该实例的业务数据。运行中的实例通过独立的回环控制端执行清理，清理成功后可继续使用；停止的实例通过独占锁清理。表结构、实例配置与安装文件保留。文件系统快照、外部备份及接收者保存的副本在此操作范围之外。


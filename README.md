# Dropdrop

在一台主机上启动 Dropdrop，同一局域网的电脑、手机和平板就能通过浏览器上传文件，或输入六位取件码下载对应批次。文件暂存在部署主机，发送者上传完成后可以关闭网页，主机需要保持运行。

当前版本为 `0.1.0-dev.0`，从源码安装使用，尚未发布到 npm。包名与 CLI 命令为 `dropdrop`，环境变量使用 `DROPDROP_` 前缀。

## 从源码启动

使用 [.nvmrc](.nvmrc) 指定的 Node.js 26.13.1 和 npm。安装 nvm 后，在项目目录执行以下命令。

```sh
nvm install
nvm use
npm ci
npm run build
npm start
```

启动后，终端显示访问地址与二维码。设备连接同一局域网后，打开地址或扫码即可使用。服务默认选择可用的物理网卡 IPv4 地址和空闲端口，多网卡时会列出其他候选及对应的 `--host` 参数。自动选择会跳过链路本地和常见代理虚拟网段。

本机试用可以固定回环地址与端口。

```sh
npm start -- --host 127.0.0.1 --port 8787
```

局域网设备访问时，使用终端打印的局域网地址。若访问失败，检查主机防火墙与 Wi-Fi 的设备隔离设置，或用 `--host` 指定主机实际的 IPv4 地址。

## 上传与取件

1. 选择“上传”，添加 1 至 20 个文件，设置最大下载次数、有效期和可选密码。最大下载次数支持 1 至 1000 次，有效期可选 1 分钟、1 小时、6 小时或 24 小时。
2. 上传完成后获得六位取件码。上传页可查看已启动下载次数，也可撤销整批文件。
3. 接收者选择“下载”，输入取件码及访问密码，查看并下载该批次中的文件。
4. 下载默认由浏览器的下载管理器保存。支持保存选择器的安全上下文还会显示“选择保存位置”入口，手机上的具体保存行为由浏览器和系统决定。

查看文件清单不消耗下载名额。同一浏览器接收会话在首次有效下载时占用一个名额，之后下载同批其他文件或通过 HTTP Range 续传共用该名额。上传者设置的下载次数与服务器同时允许的数据流数量分别控制。

每个批次最多包含 20 个文件，可分批上传更多文件。ZIP、RAR、7z 等已有压缩包可以直接上传和下载，每个压缩包计为一个文件，大小受单文件上限约束。传输时保持原始内容，压缩包由接收者自行解压。

网页支持多选文件，暂不支持直接选择文件夹或保留目录层级。需要传输整个文件夹时，可先在设备上压缩为一个文件再上传。

服务通过流式读写处理文件。上传中断后需要重新上传对应文件，当前版本尚未提供上传分片续传。

## 自动清理

下载名额耗尽后，新接收会话会看到“无下载名额”，已经获准的传输仍可继续。当所有已计数会话完成整批发送或续传窗口结束，且活动传输已收尾后，服务会删除该批次的暂存文件和关联元数据。续传窗口通常为最后活动后 10 分钟，并受批次有效期限制。

批次过期或上传者主动撤销时，服务会中止活动传输并清理文件。删除失败会自动重试。批次元数据、文件名、哈希、下载授权及传输记录随批次清除，取件码摘要和失效原因会再保留 24 小时，用于返回明确的业务提示。

“发送完成”表示服务端已发送相应字节。接收者是否保存或阅读文件无法由服务端确认。清理范围是实例内的文件和业务记录，接收者副本、系统快照及外部备份由各自持有者管理。文件删除和数据库记录清除无法保证底层介质上的不可恢复擦除。

## 启动参数

在 `npm start --` 后追加参数，完整帮助可通过 `node dist/apps/cli/src/main.js --help` 查看。

| 参数 | 用途与默认值 |
| --- | --- |
| `--host IPv4` | 绑定网卡地址，默认自动选择。使用 `0.0.0.0` 可监听全部 IPv4 接口 |
| `--port 端口` | 默认自动选择空闲端口，可用 `DROPDROP_PORT` 设置。显式指定的端口被占用时启动失败 |
| `--data-dir 目录` | 指定实例目录，优先于 `DROPDROP_DATA_DIR` |
| `--cert 证书 --key 私钥` | 同时提供时启用 HTTPS |
| `--max-file-bytes 字节` | 单文件大小上限，默认 10 GiB |
| `--max-batch-bytes 字节` | 单批次大小上限，默认 20 GiB |
| `--total-bytes 字节` | 实例文件容量预算，默认 50 GiB |
| `--max-active-downloads 数量` | 全局同时下载流数，1–64，默认 4 |
| `--max-active-uploads 数量` | 全局同时上传流数，1–16，默认 2 |

容量参数使用整数 bytes，1 GiB = 1,073,741,824 bytes。服务还会检查磁盘剩余空间，并预留 1 GiB。同一接收会话最多同时下载两个不同文件，每个浏览器最多同时上传一个文件。

首次启动时，请选择新目录或空的用户专用目录。省略目录参数和环境变量时，使用当前用户的系统应用数据目录，其子目录名为 `Dropdrop`。终端会打印实际实例目录，后续清理时使用该路径。升级前已经创建的实例可通过 `--data-dir` 指向原目录，或用 `DROPDROP_DATA_DIR` 设置其路径。

## 本机清理

`cleanup` 用于清空指定实例的上传文件、临时文件、业务记录、会话和缓存。先用只读预览核对目标目录与数量，将示例路径替换为启动时打印的实例目录。

```sh
node dist/apps/cli/src/main.js cleanup --data-dir ./dropdrop-data --dry-run
```

确认目标后，移除 `--dry-run` 即可执行清空。运行中的实例会取消活动传输并进入清理状态，清理成功后可继续上传新文件。服务停止时也可执行该命令。表结构、实例配置与安装文件保留，追加 `--json` 可获取结构化结果。

## 使用范围

- 普通 HTTP 适用于可信局域网。需要加密链路时，使用设备信任的证书配置 HTTPS。
- 六位码是短期访问凭据，应只分享给预期接收者。可选密码提供额外访问限制。
- 当前版本重启服务后会使旧批次和会话失效，并清理残留数据。需要继续传输时，重新上传获取新码。
- 将多个文件自动打包为 ZIP 下载、直接上传文件夹和跨进程重启续传尚未提供。

## 构建与打包

```sh
npm run format:check
npm run lint
npm run typecheck
npm run docs:check
npm run build
npm pack
```

`npm pack` 将 CLI、网页静态资源和数据库迁移打包到本地 tarball。网页资源随包提供，运行时使用本机文件系统和 SQLite 存储。
